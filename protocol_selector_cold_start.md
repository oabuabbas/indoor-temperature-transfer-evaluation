# Exploratory selector cold-start evaluation

Designed after observing preceding site results and history sensitivity; not preregistered, independent, or confirmatory. Compare availability and performance of fixed candidate models and rolling selectors as a new sensor accumulates history, using the same 6-hour NEST source model and preprocessing as `protocol_selector_history_sensitivity.md`. Define data start t=0 as 2021-01-01 00:00 in the PLEIA UTC-parsed axis, and the first full 96-row day of the ThermBuild ordinal axis. Use three separate forecast-issue phases: [7,14), [14,30), and [30,60) days; target must be strictly before each phase's end. Selection occurs at each phase start, using 7 days in phase 1; 7 and 14 days in phase 2; 7, 14, and 30 days in phase 3. All selection examples must have issue at or after start minus history length and target strictly before phase start. Thus the initial phase tests actual availability after a week, and selection is updated at day 14 and day 30 for this cold-start exercise (unlike monthly updates in the earlier experiment). No training, tuning, calendar hour or weather inputs on target; ties use persistence, daily, then source ridge.

Require at least 24 test rows and 24 prior examples for every history length available in that phase; exclude entity-phase from all methods if not met. Compare each eligible entity on identical test rows against persistence, daily and fixed source ridge. Average error within each entity, then equal-entity within house, equal-house for Germany; PLEIA equal-sensor. Report available/eligible entities and summary, decisions, counts and individual outcomes. Common support is guaranteed within a phase; populations can differ across phases or sites, so don't attribute changes between phases solely to time. Report counts of phase eligibility and caution that the systems still depend on reliable prior labels, assumed time axis, and sufficient observations; no operational deployment, source-site independence, uncertainty interval or population claim. All history feature rows must start no earlier than 18 hours after origin, so their prior-day feature never uses pre-origin readings. The actual prediction is issued after the hourly input bin closes, not at its start.
