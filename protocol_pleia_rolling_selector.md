# Exploratory rolling selection on PLEIAData

Written after seeing PLEIA and ThermBuild results, including the ThermBuild rolling selection; not preregistration or independent confirmation. Reuse the same NEST-only 6-hour daily residual ridge, features and penalty as `protocol_thermbuild_gating.md`, without local fitting and without time-of-day or weather as features. Compare persistence, daily-seasonal, source ridge and a selector whose candidate and tie order are persistence, daily, source ridge. Select separately per mapped temperature sensor on the previous 30 days; hold fixed for the next 30 days, requiring at least 24 valid validation examples and 24 valid evaluation examples. PLEIA raw dates are parsed as UTC per earlier pipeline; exact local-clock interpretation is not confirmed and results must not be described as verified civil time. Each hourly observation averages at least four observed ten-minute slots and is available only after the hour ends; apply 15–40°C filter before averaging, no imputation. Use validation issue hours >= start-30 days, with target-hour start strictly before the block boundary; test issue-hour start >= boundary with target-hour start < block end. This ensures the last underlying target hourly observation occurs no later than the boundary. Boundaries begin 2021-01-31 00:00 UTC and continue in 30-day intervals up to 2021-12-18 00:00 UTC, with final partial interval. Same candidate rows per sensor-block, omit all candidates together for ineligible sensor-blocks.

Aggregate test errors over eligible time points per sensor, then equal weight sensors for the overall average; count sensors and blocks and report selections. Additionally calculate scores on sensors with at least 8 eligible blocks as a coverage sensitivity analysis, chosen before generating results. Describe each group as sensor-weighted, not independent buildings, and don't interpret the two sites as independent samples or make population significance claims. Missingness, occupancy, timezone and timestamp convention remain uncertainties, and the selector requires prior labels. No tuning based on future outcomes. Store raw results by sensor and block for audit. Because all prior PLEIA results informed our research design, this is an exploratory transfer check, not untouched external validation.
