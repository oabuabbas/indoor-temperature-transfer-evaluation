# Bremen office dataset: structural and availability audit

Before computing Bremen forecast errors, inspect the four CSVs in the University of Bremen ComNets repository snapshot `d83ff1e66d41ac8f77a44d5d94fb877b00b842eb`. Source states four office rooms, UTC timestamps, temperatures in °C, and generally one-minute sampling; locations may share a building or site and must not be treated as four independent sites. Data owner/author attribution and CC BY 4.0 are required. Record file sizes, local SHA-256, and Git blob SHA-1 matched to the repository metadata pinned to the commit. SHA-1 is Git object identification, not a modern collision-resistant research checksum.

Read raw CSV `Time,Temperature`, parse UTC, count invalid values/timestamps, nonmonotonic timestamps, raw duplicates and missingness. Exclude all observations at duplicated exact timestamps, and apply 10–45°C inclusive before aggregation. Floor observations to the UTC minute and average in each observed minute; aggregate equal-weight observed minute means into 10-minute slots requiring at least five distinct observed minutes; aggregate equal-weight qualified slot means into hourly bins requiring at least four of six qualifying slots. Do not interpolate. Reindexing for coverage retains missing bins. This sampling adaptation is necessary for Bremen's approximate minute resolution; it differs from IDEAL's nominal 12-second sampling, so site comparisons must acknowledge it. Save hourly values for potential future forecasting and counts/coverage only, not forecasting errors.

Only quality metadata may be inspected before the separate locked evaluation plan. The dataset's preprocessed labels, timestamp accuracy, sensor calibration, building relationships and actual recording/communication delays are not independently verified. The decision to consider this new dataset followed prior IDEAL outcomes and policy formulation, so final external comparison is a test of that fixed policy at this site, not a prospectively registered population study.
