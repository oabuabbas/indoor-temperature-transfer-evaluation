# Joint and state-associated synthetic missingness, locally fixed v1

Fixed after viewing prior IDEAL and Bremen results, but before joint/state scenario outcomes. Exploratory, not public preregistration. Four Bremen room series are not independent sites and common infrastructure relationship is unverified; common outages are counterfactual assumptions.

Use the verified data, IDEAL source model, windows, 30-day selection, six-hour horizon, route and hourly-end issue semantics of `protocol_bremen_outage_stress_v1.md`. Mask histories and issue inputs; never make forecast decisions using unmasked future target. Use five reproducible replicates of each scenario, NumPy default_rng with scenario-specific seeds as below and array order South_2, South_5, South_8, South_9 over hourly bins 2023-01-25 to 2024-01-01 exclusive.

Scenarios, seed = 20261029 + scenario_code*1000 + replicate*10 + optional room index, replicate 0..4:
- `common_iid10` code 11: one shared Bernoulli(0.10) mask applied to every room; seed omits room index. This is one shared stochastic mechanism, not four replicated outages.
- `common_block24_14d` code 12: one shared periodic mask with 24 consecutive hours per 336 hours, one random phase uniformly drawn using shared seed.
- `temperature_dependent` code 13: independent draws by room using room-specific seed; at hour t use p=0.50 if the prior hour's **unmasked** quality-filtered temperature >=25 C, otherwise p=0.05 (including missing prior measurement). This is an explicitly hypothetical state-dependent failure mechanism, not a model fitted to sensor failures. The latent unmasked previous temperature is used ONLY by the retrospective simulator to generate the failure process, never by the forecasting model; in practice it may be unavailable. Threshold and probabilities are illustrative, do not claim causation or precision.

For each scenario/replicate/room save coverage and branch accounting with denominator all issue opportunities; paired fallback vs persistence MAE and extra fallback opportunities on (i) original unmasked target as retrospective oracle, (ii) the same target also required to survive the artificial mask at its future time and natural-quality filter (same-sensor-observed). Distinguish these regimes: (ii) can still assume sensor values promptly arrive, and its errors are selected by target observation; neither estimates actual deployment or network uptime. Summarize equal-room MAE for matched supports and scenario means/ranges across masks, never interpret masks as site-level statistical uncertainty. Also count all-four-rooms simultaneously ready on issue timestamps and all-four-rooms simultaneously having masked sensor targets; this is conditional on defined common windows, not building uptime. Same pre-masked issue times with no-outage policy provide a secondary matched-support degradation comparison. Count warm/cool issue opportunities conditional on observable latent prior-hour values; this state is an oracle diagnostic and only defines strata, not a forecasting input or evidence of real failure pattern.

Verify SHA256 of hourly files and frozen source counts; record protocol hash. Baseline no mask must reconstruct saved Bremen method results; do not overwrite old results. No energy, control or population inference.
