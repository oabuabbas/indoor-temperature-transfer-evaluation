# IDEAL nonlinear tuning and holdout comparison v1 — post-result

This protocol is locally fixed after prior IDEAL holdout outcomes (including the earlier fixed nonlinear model), Bremen and Bolzano results. It is not a fresh holdout, public preregistration or independent replication. The following new candidate-specific holdout outcomes are not used for candidate selection; nevertheless, earlier selector, local-ridge and earlier fixed boosting holdout outcomes are already known. No claim of blinded hypothesis confirmation.

## Development-only candidate choice
Use the predefined IDEAL development validation homes and their exact saved `ideal_dev_local_home_months.csv` rolling-selector evaluation windows starting 2017-10-01 through 2018-01-01 (inclusive), with target-hour start strictly before 2018-02-01; verify every (home,sensor) belongs to `dev_role=validation`, no overlap with source or holdout IDs, no duplicate windows, prior selection and test row counts reproduce existing counts from hourly data, and `target_start < month boundary`. All models have features temperature t,t−1,t−18 and target residual target minus prior-day value; fit on the 30-day complete training examples before month, no future observations or external predictors. Preserve the original >=24 history and test rule and same common support. Compare exactly three new fixed candidates, no tuning on any holdout-home data or their errors:
- `shallow`: squared loss, 60 iterations, learning_rate 0.05, max_leaf_nodes 5, min_samples_leaf 40, l2_regularization 20.
- `moderate`: squared loss, 100 iterations, learning_rate 0.05, max_leaf_nodes 10, min_samples_leaf 30, l2_regularization 10.
- `richer`: squared loss, 140 iterations, learning_rate 0.05, max_leaf_nodes 20, min_samples_leaf 20, l2_regularization 1.
All are scikit-learn HistGradientBoostingRegressor with early_stopping=False and random_state=20261029 and other defaults. These are illustrative fixed candidates; not comprehensive tuning. For every validation house and candidate pool absolute errors across its eligible months; choose smallest equal-house mean MAE over all contributing validation houses, tie order shallow, moderate, richer. Save all candidate window and house outcomes, grid, versions, and a separate choice JSON with hashes and source history artifacts. Stop if an output exists; no candidate depends on holdout metrics. Development is also not independent of previous work: selection and data quality known from earlier stages.

## Later holdout comparison
Only after selection file exists and verifies protocol/candidate/window artifacts, evaluate the one selected candidate on the subset of original IDEAL holdout eligible home-months with issue windows beginning 2018-02-01 through 2018-06-01, and their original timestamps by reconstructing history/test and checking prior saved row counts. Verify holdout and development house disjointness, selected sensor IDs and original holdout protocol hash. Existing holdout's precomputed MAEs for selector, local ridge, fixed source and earlier fixed nonlinear are known; reaggregate the original saved per-window outcomes for these later months only, then compare the selected candidate to those outcomes on exactly the same eligible rows and require complete home/month coverage. The original primary selector-minus-local comparison remains primary for the original paper; this is a new secondary post-result analysis. Store selection hash, test window/house errors and detailed results. To make matching support auditable, test rows come from the identical `windows` function and original hourly series; count equality alone does not by itself prove original physical timestamps or prior features independently.

Compute MAE per house pooled across months, then equal-home MAE; home-wise wins/ties/losses for new candidate vs selector/local/old boosting (1e-8 tolerance), months and counts, and development vs holdout support counts. No p-values, population confidence intervals or claims of cross-region/climate generalization. Do not infer energy savings, control or deployment. Require one contributing row per eligible original window and same per-home n and months. Never overwrite previous files. Output versions and hashes. Record software environment and failures. If candidate missing or results already exist, stop and preserve.

Temporal development outcomes end before 2018-02-01, and secondary holdout outcome windows start at or after 2018-02-01. The first holdout month can use its own preceding 30 days of local labeled history, including January: this is allowed test-time adaptation, not a gap or separation of all local inputs. Both cohorts are separate homes but share one geographically clustered region, so this is not independent-location validation. A partial development process was stopped before it saved or printed candidate outcome values so this temporal split could be specified; the revised protocol was fixed before the final development selection and holdout candidate errors.
