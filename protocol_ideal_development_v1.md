# IDEAL chronological development experiment v1

Exploratory development only, defined after other-site results and quality summaries but before any IDEAL forecast errors. This is not external registration. Never compute holdout-home forecast errors under this protocol. Holdout house assignment from `protocol_ideal_house_holdout.md` remains locked.

Work only with homes assigned development and one room sensor per home. Sensor candidates require successful wide 10–45°C coverage audit (`coverage_eligible`), position flag 0, no time reversals, a matching original sensor/room/house metadata record, and a named raw room-temperature member. Select exactly one candidate deterministically per home: prefer metadata room type `livingroom`, then `kitchenliving`, then `bedroom`, then all others; break ties by ascending sensor ID. This sampling uses whole-record coverage and metadata; it defines a retrospective study cohort and does not simulate selecting sensors at installation. Report sample attrition and selection. If selection yields no candidate, exclude home; no forecast performance informs selection.

For each selected sensor, parse raw UTC timestamps and tenths of °C. Retain only 10–45°C. De-duplicate identical timestamps using first occurrence, refuse time reversals or values outside 2016–2018 timestamps; data gaps remain empty. Within UTC-aligned 10-min slots require at least 25 valid distinct timestamps; each slot temperature is the mean of those observations. For each UTC hour require at least 4 valid slots and take the unweighted mean of valid slot means. Predictions are issued at or after the end of the input hour. Use only temperature. Do not fill missing hours, use weather, derive calendar hour, or access holdout series for modeling.

Split development houses into source and development-validation deterministically using SHA-256 first eight bytes, big endian, of `ideal-development-source-v1:<homeid>`: source if the unsigned value is less than 7/10 of 2^64, validation otherwise. Group by house; no home in both. This additional split is exploratory and not a replacement for the locked test holdout.

Train a source daily-residual ridge (penalty 100; standardization fitted on source only) on source-home eligible samples with forecast target-hour start strictly before 2017-09-01 00:00 UTC. Target-hour bins finish at or before cutoff. Develop only on separate validation homes: forecast issue-hour start >= 2017-10-01 and target-hour start < 2018-06-30 00:00 UTC, horizon 6 h, with monthly issue windows beginning 2017-10-01 through 2018-06-01. (This deliberately ends at the start of the last day, not at its end.) Compare persistence, previous-day same target hour, source ridge around daily baseline, and per-room history-based selector; all use identical eligible rows. For a target t+h, prior-day reference is observed at t-(24-h), and lag one hour is t-1. History selector selects lowest MAE among the three fixed candidates using the previous 30 days of issue hours whose targets are strictly earlier than each monthly window boundary; require at least 24 selection and 24 evaluation examples, exclude the window for all models if unmet, and break ties persistence, daily, ridge. The monthly selector requires prior target observations and is not zero-shot. No target model fitting. Unseen houses with fewer than the required observations are excluded from that window, logged; don't fill.

Calculate per-home test MAE pooled across eligible issue times and equal-home summaries (one sensor each); include evaluation counts and selection frequencies. No confidence interval, significance, causal or energy-saving claim. Source homes may contribute different counts of source rows; this is sample-weighted source training and should be reported. Selection windows, filtering, source cutoff and test periods may change after inspecting development results; if changed, document v2. Before any holdout scores, freeze a separate full test protocol that specifies the final model, features, sensor and time selection, primary comparison, exclusions, analysis and sensitivity. IDEAL remains one geographically clustered regional dataset.
