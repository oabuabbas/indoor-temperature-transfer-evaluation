# PLEIA raw temperature filter sensitivity

Exploratory post-hoc investigation, written after earlier NEST/PLEIA outcomes and after inspecting sample raw values from four excluded PLEIA sensor IDs. Not preregistered or confirmatory. Evaluate strict target 15–40 °C versus expanded target 10–45 °C. These are plausible filtering assumptions, not verified validity ranges or claims that excluded values are erroneous. NEST source filter remains 15–40 °C throughout, so this isolates target-side preprocessing changes rather than jointly changing the training domain.

Aggregate PLEIA raw samples exactly as `external_pleia.py`: average per ten-minute slot, require >=4 valid slots/hour, no target fill, explicit sensor offsets UTC. Distinct filtering ranges can produce different hourly means even for the same hour; timestamps can be aligned but labels and input values need not be identical. Record target-sensor/hour overlaps and target value changes for matched evaluation times.

Train a pooled NEST-only temperature-and-hour ridge using the same external_pleia.nest_data, training cutoff < 2020-11-01; compare with persistence. Horizons 1, 6, 24; January 2021 target sensor calibrates separate nominal 90% intervals per range/model, test target Feb–Dec 17 and input-hour start >= Feb 1. No target fitting of point models. For each sensor/horizon evaluate each range on (a) all eligible target times in that range and (b) issue timestamps common to both ranges. Use at least 24 calibration and 24 test observations and require sensor eligibility in both arms; report excluded sensors. Same source model for ranges. Record means by sensor and max/mean absolute changes in target values on common timestamps. No causality, p-values, claim of global robustness or perfect matched labels. Further month and sensor distribution analysis and justified physical ranges are still required.
