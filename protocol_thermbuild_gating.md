# Exploratory prospective model selection on ThermBuild

Written after seeing aggregate and block results for ThermBuild, so the exercise is not an untouched confirmatory test. Forecast horizon 6 h. Candidate forecasts are fixed source-trained NEST daily residual ridge, persistence, and previous-day reference from `protocol_thermbuild.md`; no target-site model fitting. Select separately per room and fixed 30-day evaluation block using minimum MAE on the immediately preceding 30 days. Freeze at the block start. Ties use the order persistence, daily, source ridge. Validation requires issue >= start-720 and target strictly < start. Test requires issue >= start and target strictly < start+720 (or end of recorded grid), leaving a six-hour boundary gap in target time to prevent leakage; all candidates use the same valid rows. Require >=24 observations in validation and test, otherwise exclude that room-block for all candidates and gate. The first 30 days are selection history, never test; last partial block is retained if requirements are met. Performance per room is weighted by eligible forecast count within that room, then equal-weight rooms within house and houses in combined summary; block comparisons use equal-room means when all 7 rooms are eligible.

Report retrospective selection frequencies, number of eligible room-blocks, full-period MAE and block MAE for each strategy on common eligible rows. No re-selection based on test labels within a block. Do not label this formally registered, independent confirmation, or a causal or energy saving test; the site/time assumptions in the original protocol remain. Comparison ignores costs, sensor errors and latency, and its rolling selection depends on the availability of prior target labels.
