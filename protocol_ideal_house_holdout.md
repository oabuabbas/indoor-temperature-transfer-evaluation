# Provisional house-level split for future IDEAL evaluation

Defined after seeing other datasets' results and IDEAL metadata and a few raw-file schema samples, but before computing any IDEAL forecast errors. Exploratory data-quality review can continue on all homes, but do not compute or inspect candidate forecast errors on the holdout until a separate full analysis protocol is frozen using development data only. This split is a local record, not independently timestamped public preregistration. If test outcomes are inspected before protocol freeze, reclassify as exploratory, never silently claim blind validation.

Assign every home listed in the original `home.csv` to exactly one group using SHA-256 of UTF-8 `ideal-room-transfer-holdout-v1:<integer-homeid>`. Convert the first 8 bytes to an unsigned big-endian integer. If this value is less than 7/10 of 2^64, assign to development; otherwise assign to holdout. This deterministic split uses no values, coverage, sensor attributes, or outcomes. All rooms/sensors from the same home inherit the home split. Home eligibility is determined separately from the audit with explicitly stated thresholds; report attrition by split without treating rooms as independent homes. The dataset is geographically clustered; homes are not independent climate regions.

The current source NEST data are later than IDEAL measurements; any model comparison is a retrospective cross-building test, not a chronological deployment emulation. Forecast eligibility, timestamp and aggregation rules, metric weights and target observation windows remain to be finalized; this document freezes only assignment and the rule reserving forecast outcomes. If source chronology is changed or another source is chosen, disclose that decision and any test-set access. A future manuscript must identify all prior target inspection and avoid universal population claims.
