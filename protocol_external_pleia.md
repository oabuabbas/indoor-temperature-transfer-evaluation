# Cross-site NEST → PLEIAData pilot: frozen before running

Exploratory protocol written after NEST-only results were inspected and before examining PLEIA raw temperature values or external model results. It is not preregistered or confirmatory. Source data are NEST (Switzerland), target data are PLEIAData v3 (one university building in Murcia, Spain). The target consists of sensors and rooms, not independent buildings.

## Clock and features
PLEIA raw sensor timestamps include explicit numeric UTC offsets; parse each with `utc=True`, use absolute UTC hours, and derive clock features in Europe/Madrid. The PLEIA weather timestamp convention cannot be verified from the available source documentation. Therefore this pilot uses no weather or solar inputs anywhere, neither source nor target; there is no unjustified clock alignment. NEST source local naive timestamps are used as originally represented; uncertain DST semantics remain a limitation.

Predict future hourly mean indoor temperature with issue-time observed current and preceding hourly temperature and local hour sine/cosine. Target horizons are 1, 6 and 24 hours. This is passive forecasting with no future HVAC control or weather, not a control-conditioned or causal model. Source data from all three NEST units are strictly before Nov 2020, with both annual files processed separately. A single pooled source linear ridge for each horizon is fit to predict temperature change with source-only scaling. Compare a persistence baseline on precisely the same samples.

## Target selection and splits
Read only raw `data-sensor.csv` and `relations-sensor.csv` from versioned archive. A sensor must map unambiguously to a block and room. Parse numeric temperature, treat outside 15–40 °C as invalid based on provider code; this is a modeling filter, not ground truth. Aggregate multiple raw points within each absolute ten-minute slot using their mean, then aggregate slots within each hour. Require at least four distinct valid 10-minute slots per hourly mean; no target filling, interpolation, forward-fill or processed temperature values. Current, previous-hour and h-ahead target must all pass this observed-data rule. Target timestamp determines split. Use January 2021 only to calibrate each sensor's intervals; Feb 1–Dec 17 inclusive test held-out. No PLEIA target values are used to fit or select source model coefficients. Per-sensor calibration requires >=24 observations; no intervals are produced where it fails. Report point metrics separately for all eligible sensors and intervals only for sensors with sufficient calibration. Drop identical source mappings and exclude conflicting sensor mappings; no weighting of sensors by number of samples in summary.

Estimate nominal 90% interval by per-sensor January absolute residual quantile with finite-sample order statistic; note target-site labels are used for calibration even though model training is zero-shot. Coverage is empirical on Feb–Dec and not guaranteed under serial dependence or shift. Report per-sensor results, number of sensors/rooms/blocks and data availability; aggregate equally by sensor. UTC interval bin boundaries represent [hour,hour+1); no sensor values from the future hour enter input. Accounting for horizon uses forecast target bin. Per-sensor quantile errors and filtered ranges should be audited, and assumptions and costs stated. One site cannot establish global generalization.

Correction after discovery: test input-hour start must be at or after February 1, after calibration ends; the target must also be inside the test period. The pre-correction outputs are archived and superseded.
