# Frozen local Bremen fallback evaluation v1

Written after inspecting Bremen file metadata and quality, but before computing Bremen forecast errors or policy performance. Policy and settings were chosen after IDEAL development/holdout results and IDEAL's post-result availability audit; not public preregistration, not an untouched conceptual design and not independent verification by another analyst. Bremen is a separate real-world dataset, but its four office rooms are not assumed to be four independent sites or representative buildings. The specific building relationships, measurement latency and sensor calibration are not verified.

## Source and time order

Use the fixed temperature-only IDEAL transferred daily-residual ridge from `protocol_ideal_holdout_v1.md`, refit from the **same** 55 source-development houses and 125,779 eligible source rows with target hours before 2017-09-01 UTC; no IDEAL holdout used to fit. Before evaluating Bremen, verify these counts and source selection. Four pinned Bremen CSV files at commit `d83ff1e66d41ac8f77a44d5d94fb877b00b842eb` are verified by Git blob identities. Quality preprocessing is specified in `protocol_bremen_quality.md`: UTC, 10–45°C, >=5 distinct observed minutes per 10-minute slot, >=4 qualifying slots per hour, equal-slot means and no imputation. This differs from IDEAL's 12-second-source rule.

## Decision and observed outcomes

Evaluate fixed hourly issue windows per sensor from 2023-03-01 00:00 UTC up to 2024-01-01 00:00 UTC, broken at calendar-month starts. Issue-hour start t must be >= month start and target-hour start t+6h strictly < month end; the prediction is available only once the entire input hour finishes. Each sensor's previous 30-day history at each month start contains only examples whose issue >= start−30 days and target-hour start < start, and needs >=24 eligible complete-feature/target rows for selector choice and local ridge fitting. Selection uses history MAE among persistence, previous-day and source ridge with ties in that order; keep choice fixed for the month. No requirement on the future number of target measurements is used to decide whether to forecast.

The previously formulated fallback policy is: if selector history and its full feature vector (t,t−1,t−18) are available, issue its chosen prediction; otherwise if the hourly measurement at t is available, predict persistence; otherwise if t−18 is available, use the prior-day reference; otherwise abstain. Check historical/current inputs only for the decision. The future target value is used only after it is observed to score forecasts. Also evaluate always-persistence, daily reference, fixed source ridge and a locally fitted 30-day ridge on their own available inputs/history for descriptive comparison. The local ridge is a comparator and not included in selector candidates.

## Primary measurements and missingness

Report for each sensor and method (a) coverage of **all expected issue opportunities** and branch/abstention counts without using targets, (b) the fraction of issued forecasts with subsequently observed target, and (c) MAE only for issued forecasts with observed target. Also report equal-sensor mean MAE on common issue/target support for fallback versus always-persistence: both methods issue and target is observed. This paired comparison is the principal accuracy comparison; its support necessarily requires the current reading and cannot measure fallback's additional daily-reference-only forecasts. Report those extra branches separately. No filtering by hindsight monthly test-count, no imputation, no use of outcome-derived bins for policy selection. Also report per-sensor results, choice counts and missing-target counts. Own-support errors reflect selection/missingness and cannot be interpreted as direct comparisons across methods.

No statistical significance, population interval, causal explanation, energy saving or controller performance claim is justified by four correlated rooms in one dataset. All policy accuracy is conditional on observed targets and source-quality thresholds. Never revise the primary metrics or policy after seeing errors; further experiments must be labeled post-result exploratory. Preserve IDEAL original holdout outcomes.
